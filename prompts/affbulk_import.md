# Импорт сгенерированного текста в AffBulk: правила для Claude

Промпт для сессии Claude Code с подключённым MCP AffBulk. Вход: готовый запуск `runs/<run>/` (есть `04_final.json`, `00_knowledge_base.json`, `01_brief.json`). Результат: сайт и страница в AffBulk, собранные по образцу уже существующих сайтов. Python-сборщик `affbulk/build_page.py` применяет правила компоновки механически; решения по контенту (SEO, подписи, отзывы, подбор картинок) принимает Claude по правилам ниже.

## 0. Что запрещено и что требует подтверждения

- Любой write-вызов (`websites_create`, `pages_create`, `pages_update`, `pages_delete`, `upload_*`) выполняется с `userAuthorized: true` только после явного «да» пользователя на конкретное действие. Перед первым write показать план: домены, донор, номера сайтов, список блоков, найденные расхождения (раздел 8).
- Не выдумывать факты: суммы, проценты, сроки, лицензии, провайдеров брать только из базы знаний (`00_knowledge_base.json`) и из `04_final.json`.
- Не удалять и не перезаписывать существующие сайты и страницы без отдельного ответа пользователя. Если домен уже есть в AffBulk (`websites_find` по `domain`), остановиться и спросить: использовать готовый сайт, пропустить или перезаписать `index`.
- Не привязывать чужой CDN-профиль и не копировать `cdnProfile` с донора: у каждого сайта свой Cloudflare-профиль. Профиль и регистратор привязывает пользователь.

## 1. Сайт

1. `websites_find` по домену: сайта быть не должно (иначе см. раздел 0).
2. Донор: самый свежий сайт того же бренда на том же языке (`websites_find` с `brandName` и `language`, сортировка по `createdAt`). Если нет — донор того же бренда на любом языке и перевод строк шапки и подвала. Прочитать его через `websites_find_one` с `populate: "deep"` (ответ большой, он сохраняется в файл, разбирать скриптом, не читать целиком).
3. `websites_create` с полями донора: `template` (Template LeadsCount, id 16), `language`, `contentLanguage`, `targetCountry`, `websiteTemplateColors`, `fonts`, `header`, `footer` (с `payments`), `analyticsType: "umami"`, `index: true`, `favicon`, `logo`, `defaultHeroImage`, `affiliate_link` (id 1, переменная `{{rezerv_casino}}`). Без `cdnProfile` и `registrarProfile`. `brandName` как у донора.
4. Шапка: `navLinks` и кнопки с `{{rezerv_casino}}`, `linkStatus: "affiliate"`, тексты на языке сайта; внутренних ссылок нет, пока нет внутренних страниц. Подвал: те же правила.
5. Картинки бренда: `media_folders_find` → папка бренда (hero, лого, фавикон) и вложенная папка `bonuses`/`Bonus`/`Bonuses` (картинки бонусов); `upload_find` с `folderId`. Если у бренда есть подпапка `new`, смотреть и её: актуальными считаются файлы, загруженные вместе с базой знаний `*-new`.

## 2. Страница: набор блоков

Используются только эти блоки и только в этом порядке:

| # | Блок | Сколько | Зачем |
|---|---|---|---|
| 1 | `blocks.hero` | 1 | Первый экран: картинка, H1, одна кнопка |
| 2 | `blocks.swiper` | 3 | Плитки игр: слоты, crash/instant, live |
| 3 | `blocks.preview` | 1 | Плитки бонусов с картинками из папки бонусов бренда |
| 4 | `blocks.article` | N | Обычный текст: вводный абзац и по одному блоку на H2/H3 |
| 5 | `blocks.call-to-action` | 5 | Кнопка перед каким-либо H2 |
| 6 | `blocks.reviews-2` | 1 | Отзывы игроков, после статей |
| 7 | `blocks.faq` | 1 | Вопросы и ответы из текста |
| 8 | `blocks.promo` | 1 | Последний блок: плашка с бонусом и кнопкой |

Не использовать, пока пользователь не попросил: `author`, `demo`, `offer-list`, `section`, `gallery`, `labels`, `form`, `popup`, `ai-summarize`, `lucky-spin`, `preferred-source`, `reviews` (первый вариант отзывов). Блок не добавляется ради блока: у `offer-list` нет данных о других брендах, у `demo` нет iframe демо, у `author` нет автора. Перед сборкой вызвать `page_presets_available_components` с `websiteId` и убедиться, что все 8 блоков доступны шаблону.

## 3. Наполнение блоков

**Hero.** `title` = H1 из `04_final.json` (дословно). `label` = одна строка с приветственным бонусом из базы знаний на языке страницы (например «Do NZ$20 000 + 350 darmowych spinów»). `mainLabel` пустой. `background` = id hero-картинки бренда (webp 1536×500, не png на мегабайты). `buttons`: одна кнопка `main`, текст «Регистрация» на языке сайта, `link: "{{rezerv_casino}}"`, `linkStatus: "affiliate"`.

**Swiper ×3.** Заголовки: слоты / crash и instant / live на языке сайта. `variant: "small"`. Плитки одинаковы на всех сайтах (12 слотов, 12 crash, 6 live, id картинок из папок 45, 46, 47, список в `affbulk/build_page.py`, `SWIPERS`). У каждой плитки `description` — название игры, `button` с текстом «Играть» (`affiliate`). Список игр не менять и не дополнять играми, которых нет в папках. Названия игр в `description` не переводить и не транслитерировать, они остаются в оригинале (как в `SWIPERS`) на любом языке сайта; переводятся только заголовок блока и текст кнопки.

**Preview.** `title` вида «<Бренд> бонусы» на языке сайта. Один элемент на один бонус, 4–6 элементов. Элемент: `image` (id картинки из папки бонусов бренда), `content` = `<h3><strong>Название</strong></h3>` + перевод строки + короткая суть («100% до …»), `buttons` — одна кнопка `affiliate` («Получить бонус»). Подписи берутся только из базы знаний. Если картинка не соответствует бонусу из базы (другая сумма или другая акция), этот бонус не использовать с этой картинкой и записать расхождение в отчёт (раздел 8). Названия и суммы в подписи не придумывать.

**Article.** Вводный абзац (текст под H1) идёт первым Article без заголовка. Дальше каждый H2 и каждый H3 из `04_final.json` — отдельный `blocks.article`: `<h2>…</h2>` или `<h3>…</h3>`, затем тело. Уровни и порядок сохраняются. Markdown → HTML: абзац `<p>`, маркированный список `<ul><li>`, нумерованный `<ol><li>`, таблица `<table><tr><td>` (первая строка шапки тоже `<td>`, как на донорах), `**x**` → `<strong>`. Ничего не переписывать и не сокращать: текст уже прошёл проверки шага 3.

**Call-to-action (Button) ×5.** Блок `blocks.call-to-action` с одной кнопкой `main`. Ровно 5 блоков, каждый стоит непосредственно перед Article с `<h2>` (первый — перед первым H2, остальные равномерно по тексту). Не ставить CTA перед H3, перед FAQ и перед Reviews. Тексты кнопок разные («Забрать бонус», «Играть», «Регистрация», …), все на языке сайта.

**Reviews 2.** `title` на языке сайта («Отзывы игроков»), 5–6 отзывов. Поля: `username` (имя, типичное для ГЕО), `review` (1–2 предложения, 20–35 слов, от первого лица, без цифр, сумм, сроков и обещаний выплат; темы: регистрация, выбор игр, мобильная версия, поддержка, платёжные методы), `date` (в пределах последних 10 дней от даты импорта), `avatar` (id из папки `Reviews-2`: Female_1 3861, Female_2 3860, Female_3 3859, Female_4 3857, Female_5 3854, Male_1 3862, Male_2 3858, Male_3 3856, Male_4 3855, Male_5 3853; пол аватарки совпадает с именем), `rating` 4 или 5 из 5. Упоминания бренда по названию допустимы, число упоминаний ключа ограничено так же, как в тексте: смотреть, чтобы в отзывах не было больше одного вхождения ключа на отзыв. Отзывы не копируются с сайтов конкурентов.

**FAQ.** Берётся из блока текста, где список в формате `- **Вопрос?** Ответ`. Тот блок (его H2) из статей исключается: `title` FAQ = его заголовок, `faqs` = пары вопрос/ответ дословно. Ставится после Reviews 2.

**Promo.** `title`: название приветственного предложения; `description`: короткая строка «сумма + фриспины» из базы знаний; `disclaimer`: «18+», условия, ответственная игра на языке сайта (без цифр, которых нет в базе); `buttons`: одна кнопка `affiliate`; `image` = hero бренда.

**Кнопки (все).** `variant: "main"` (в шапке допускается `secondary`), `link: "{{rezerv_casino}}"`, `linkStatus: "affiliate"` — обязательно, без `linkStatus` деплой падает. `external`-ссылки не использовать (проверка `settings_find`).

## 4. SEO и метаданные страницы

- `slug: "index"`, `tableOfContent: false`.
- `seo.title`: до 60 знаков, основной ключ в начале, затем главное предложение (бонус из базы), язык страницы. `seo.description`: 120–160 знаков, основной ключ один раз, что получит игрок (игры, бонус, поддержка), без эмодзи и обещаний выигрыша. `index: true`.
- `keywords.mainKeywords`: название бренда. `keywords.additionalKeywords`: 10–15 слов через запятую на языке страницы (казино, слоты, регистрация, вход, KYC, приложение, платежи, бонусы, приветственный бонус, ГЕО и его код) — по образцу доноров.
- Без `customCanonical`, без hreflang и без внутренних страниц, если пользователь не просил иного.

## 5. Сборка

1. Создать `runs/<run>/05_affbulk_config.json` (поля см. `affbulk/build_page.py`, функция `build_page`): `website_id`, `locale` (`en`, `pl`, `it`, `no`, `uk`), `seo`, `keywords`, `hero`, `preview`, `reviews`, `promo`, при необходимости `cta_texts`.
2. `python -m affbulk.build_page <run>` → `05_affbulk_page.json` (готовый `data` для `pages_create`). Скрипт сам проверяет порядок блоков, число Swiper и CTA, позицию CTA перед H2, порядок Reviews 2 → FAQ → Promo и `linkStatus` всех кнопок; при ошибке завершается с текстом проблем.
3. Прочитать сгенерированный JSON и передать его без изменений в `pages_create` (поле `data`). Большие страницы (20–40 КБ) передавать одним вызовом; если сайт уже содержит страницу `index` и пользователь разрешил перезапись — `pages_update` с тем же `content`.

## 6. Проверка после записи

- `pages_find_one` (`populate: "deep"`) → число блоков и их порядок совпадают с `05_affbulk_page.json`, у всех кнопок есть `linkStatus`, в Preview у каждого элемента есть картинка.
- `websites_find_one` → домен, язык, шаблон, цвета, шапка и подвал на месте, `cdnProfile` пуст (его привяжет пользователь).
- Сообщить пользователю id сайта и страницы, а также что осталось сделать вручную: CDN-профиль, регистратор, деплой.

## 7. Язык и оформление

Все надписи на сайте, включая кнопки, заголовки блоков, подписи в Preview, отзывы и дисклеймер, пишутся на языке ГЕО страницы (en, pl, it, no, uk). Служебные поля и ключи схемы остаются английскими. Названия игр и провайдеров не переводятся (в том числе в Swiper).

## 9. Страницы brand-subpage (Login, App, VIP, Sports, Bonuses, Payments)

Страница бренда на новом slug (не `index`) на сайте, где уже есть главная. Собирает `build_subpage` (`python -m affbulk.build_page <run>`, тип берётся из `page_type` в `04_final.json`), конфиг — `05_affbulk_config.json` со `slug`, `seo`, `keywords`, `hero`, `cta_texts`, `home_link`, `promo`.

| # | Блок | Сколько | Зачем |
|---|---|---|---|
| 1 | `blocks.hero` | 1 | Первый экран: картинка, H1, одна кнопка |
| 2 | `blocks.preview` | 1 | Плитки бонусов (только для страниц про бонусы/промокоды: в конфиге ключ `preview`) |
| 3 | `blocks.article` | N | Вводный абзац и по одному блоку на H2/H3 |
| 4 | `blocks.call-to-action` | 2 | Кнопка перед H2: первая перед первым H2, вторая примерно посередине страницы (`SUBPAGE_CTA_COUNT`; не перед H3 и FAQ; если H2 один — одна кнопка) |
| 5 | `blocks.faq` | 1 | Вопросы и ответы из текста |
| 6 | `blocks.promo` | 1 | Последний блок: плашка с бонусом и кнопкой |

Без `swiper`, `reviews-2`, `offer-list`. Все кнопки `{{rezerv_casino}}` + `linkStatus: "affiliate"`. Ссылка на главную — одна, анкор — название бренда: в конфиге `home_link: {"anchor": "<Brand>", "href": "/"}`, builder (`link_anchor`) оборачивает ссылкой первое упоминание бренда в тексте (сначала вступление, заголовки и существующие ссылки пропускаются). Отдельного абзаца ради ссылки нет; если бренда нет в тексте, сборка падает. В ТЗ это закладывается автоматически: у блока H1 в `01_brief.md` и в запросе шага 2 стоит строка «Home link» (`textgen.brief.home_link_note`), а `writer_brand-subpage.md` запрещает писать фразу ради ссылки.

- **Меню:** по правилам раздела 10 (`affbulk/menu.py`, `plan_menu`): короткое название без бренда, замена пункта той же темы, не больше 6 пунктов в шапке, остальное в подвал. `websites_update` с `header` (`navLinks` + `buttons` без изменений) и `footer` (`text`, `payments` — id картинок, `links`). Перед записью сверить, что шапка сайта совпадает с ожидаемой.
- **Ссылка с главной на страницу:** в разделе главной, где тема страницы встречается естественно, оборачивается ссылкой `/<slug>` существующая фраза **не длиннее 3 слов** (слова не добавляются и не убираются; `affbulk.links.wrap_phrase` сам отказывает, если анкор длиннее); для заливки используется `pages_update` только с полем `content`, а перед ним главная читается и сверяется с локальным `05_affbulk_page.json` (`verify_page`: допустимо расхождение только в `preview`, сервер не возвращает его элементы).
- **Деплой:** сначала один сайт, проверка адреса страницы (на живом сайте страница отвечает на `/login` без слэша, `/login/` даёт редирект 308) и ссылок на живой странице, затем остальные.
- Все write-вызовы — по явному «да» пользователя на этот план.

## 10. Структура сайта: меню и внутренние ссылки (правила пользователя, 2026-10-25)

Базовый набор страниц сайта типа Brand: главная, `bonuses`, `app`, `promo-code`, `login`, `no-deposit-bonus`, `payments` (`textgen/sitemap.py`, `BASE_SITE_PAGES`). Что из набора реально есть на сайте, видно по `pages_find`; недостающие страницы пользователь заказывает отдельно, ссылок на несуществующие страницы нет.

**Меню (шапка `header.navLinks`, подвал `footer.links`)** — `plan_menu(header, footer, brand=…, slug=…, label=…)` в `affbulk/menu.py`, результат (включая журнал изменений) показать пользователю до записи:
1. Новый пункт не добавляется рядом со старым той же темы, а заменяет его: «Promotions» → «Bonuses», аффилиатная ссылка пункта заменяется внутренней. Тема определяется `textgen.sitemap.topic_of` (bonuses, app, promo-code, login, no-deposit-bonus, payments). То же в подвале: пункт-аналог в подвале тоже становится внутренней ссылкой.
2. Название короткое и без бренда: «Longfu88 Bonuses» → «Bonuses», «Longfu88 Login» → «Login» (`short_label`). Уже стоящие внутренние пункты с брендом укорачиваются при том же проходе.
3. В шапке **не больше 6 пунктов** (`MAX_HEADER_ITEMS`). Если шапка полна, последний аффилиатный пункт уходит в подвал (в шапке остаётся не меньше 3 аффилиатных пунктов), а его место занимает внутренний; если аффилиатных осталось 3, внутренняя страница идёт в подвал. Подвал без лимита.
4. Кнопки шапки (`header.buttons`) и платёжные иконки подвала не меняются; при `websites_update` их передают как есть.

**Анкоры внутренних ссылок** — не длиннее 3 слов (`MAX_ANCHOR_WORDS`): «Longfu88 bonus for newly registered players» → «Longfu88 bonus»; «Longfu caino login» уже годится. Это проверяют `wrap_phrase`, `check_anchors` (внутри `check_page` / `check_subpage`) и `site_link_report`.

**Перелинковка**
- Главная ссылается на **все** внутренние страницы сайта; каждая внутренняя страница ссылается на главную (анкор — название бренда, `home_link`). Внутренние страницы могут ссылаться друг на друга, только если это органично (в тексте про регистрацию упомянуты промокоды → ссылка на `promo-code`). Разделы ради ссылок не добавляются.
- Анкоры закладываются в ТЗ: шаг 1 расставляет страницы по блокам, где тема названа в заголовке или `summary` (`attach_internal_links`, строка «Internal links» в блоке ТЗ и в запросе шага 2); `Site pages - …` во входном файле задаёт набор вручную, по умолчанию — базовый набор без самой страницы. Для обзора (главной) все ссылки обязательны, для подстраницы — по месту. Конфиг страницы принимает `internal_links: [{"anchor": "<фраза ≤ 3 слов из текста>", "href": "/<slug>"}]`, сборщик оборачивает первое упоминание.
- После записи страниц сайта: прочитать их (`pages_find_one`, `populate: "deep"`) и пропустить через `affbulk.links.site_link_report({"index": content, "login": content, ...})` — пустой список означает, что главная ссылается на все страницы, все страницы ссылаются на главную, анкоры короткие.

## 8. Что обязательно вынести в отчёт пользователю

- Расхождения между картинками бонусов (по названию файла) и базой знаний.
- Конкуренты, которые не скачались, и как это повлияло на ТЗ.
- Места, где база знаний содержит «моделированные» или противоречивые данные.
- Что отзывы и подписи — редакционный контент, а не цитаты реальных игроков, и перед публикацией их нужно сверить с правилами площадок и закона о рекламе в ГЕО.
